# GUIDELINE — โฟลเดอร์ AGENT

`AGENT/` เก็บ **คำสั่งของโมเดล** ทั้งหมด แยกตามระดับชั้นของ OpenCode

```
AGENT/
├─ 01PRIMARY/      โหมดหลัก 4 ตัว (ผู้ใช้สลับด้วย Shift+Tab)
├─ 02SUBAGENT/     ตัวช่วยที่โหมดหลักเรียก
│  └─ SUBSUBAGENT/ ตัวช่วยของ Arena
├─ 03SKILLS/       ความรู้/กระบวนการ (PSTACK + BAZER)
└─ 04PLUGIN/       โค้ดปลั๊กอิน (ที่เดียวใน MAJOR ที่เป็นโค้ดได้)
```

## กฎของโฟลเดอร์นี้ (ต่อจาก R1)

1. **ทุกไฟล์ใน `01PRIMARY/` `02SUBAGENT/` `03SKILLS/` ต้องใช้ได้จริงใน OpenCode v2.0.32** — frontmatter ที่ผิดสคีมา = agent ถูกทิ้งทั้งไฟล์แบบเงียบ (โรคเก่า: `color: accent` หายทั้งตัว)
2. **ห้าม hardcode path ปลายทาง** — ไฟล์ในนี้คือ "ของ" ไม่ใช่ "ที่อยู่" ที่อยู่เป็นงานของ `MANIFEST`
3. **ภาษาหลัก = ไทย** คำเทคนิค (tool name, path, marker, สัญญา frontmatter, ชื่อ field) คงเป็นอังกฤษ
4. **ต้องมี marker ระบุตัวตน + เวอร์ชัน** บรรทัดแรกของเนื้อหา (หลัง frontmatter):
   `<!-- BAZER-MODE: <ชื่อ> v1 -->` — Console ใช้ตรวจว่าไฟล์ที่ติดตั้งตรงกับต้นทางไหม
5. **ข้อความที่เครื่องตรวจได้ (machine-checkable) ต้องเป๊ะทุกตัวอักษร** — ตัวอย่าง: หัวแผน `# GATE 1 — ARENA PLAN` (em dash ตัวจริง) · `# GATE 2 — BUILD PLAN`
6. **ทุก path / ชื่อปุ่ม / ชื่อไฟล์ ที่อ้างถึงในเนื้อหา ต้องมีจริงในระบบ** — ถ้าอ้างแล้วไม่มี = เอกสารโกหกโมเดล (โรคเก่า: README พูด v1, ไฟล์จริง v2)
7. **ห้ามสร้างไฟล์สำเนา (mirror)** — เรียกโหมดอื่นด้วย subagent จริงเท่านั้น

## Checklist ก่อน commit ไฟล์ใน AGENT

- [ ] frontmatter ผ่านสคีมา (`mode`, `color` hex 6 หลัก, `permission` คีย์ที่ใช้ได้จริง)
- [ ] ไม่มีคำขัดกันเอง — ถ้าประโยคหนึ่งห้าม อีกประโยคอนุญาต ต้องมีเงื่อนไขเวลา/เงื่อนไขบริบทกำกับ
- [ ] ระบุชัดว่า "ก่อนอนุมัติ" กับ "หลังอนุมัติ" ต่างกันอย่างไร (ถ้าโหมดนั้นมี gate)
- [ ] ปิดช่องทางอ้อมครบ (subagent / shell / glob / grep)
- [ ] สัญญารายงานปลายทางมีรูปตายตัว
- [ ] ผ่าน `ตรวจกฎ` และ `ตรวจความครบ` ใน BAZERCONSOLE
