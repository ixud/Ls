# GUIDELINE — 04PLANNOTATOR

เก็บ **ค่าที่ Console ใช้จัดการ Plannotator** (ปลั๊กอินที่ให้ผู้ใช้อนุมัติแผน)

## กฎ

1. การแพตช์ต้องเริ่มจาก **probe `plannotator-locate`** ให้เจอไฟล์จริงก่อนเสมอ — ห้ามเดาพาธ
2. ต้องเก็บ hash ของไฟล์ก่อนแพตช์ไว้เทียบ — ถ้า Plannotator อัปเดตแล้ว hash เปลี่ยน → สถานะ `broken` ให้แพตช์ใหม่
3. เป้าหมายปุ่มอนุมัติ: **มาจากโหมดไหน กลับโหมดนั้น** (`buddha` → `buddha`, `bazer` → `bazer`)
4. ถ้าแพตช์ไม่ได้ ห้ามทำให้ระบบพัง — ต้องถอยไปใช้ `submit_plan` ตามปกติและรายงานตรง ๆ
5. ทุกครั้งที่แพตช์: backup ไฟล์เดิม + บันทึก history + ตรวจ syntax หลังเขียน (ไฟล์เสีย = คืนทันที)
6. `status: design` ใน `manifest.json` หมายถึง **ยังไม่แพตช์อัตโนมัติ** — การแพตช์ทำด้วยมือผ่านการ์ดในหน้าโหมด & สิทธิ์
7. ตัวแพตช์ (`SERVER/plannotator.mjs`) แตะเฉพาะ token `switchTo:"<...>"` เท่านั้น — ถ้าไฟล์รุ่นใหม่เปลี่ยนรูปแบบ จะไม่เจอ token และรายงานว่าต้องแพตช์ (ไม่เขียนมั่ว)
8. ปุ่มของ Plannotator เป็นปุ่มเดียว (global) — รองรับ "กลับโหมดเดียว"; การสลับตามผู้เรียกอัตโนมัติต้องรอปลั๊กอินรองรับ per-agent
